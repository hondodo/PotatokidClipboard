## 编译三 flavor + 上传 yuntu 供下载验证

**产物**：`pscreen/potatokid_screen` 下依次 `flutter build apk --debug --flavor {tv,phone,board} --dart-define=APP_FLAVOR={同值}`，三种 flavor 各出 universal + arm64-v8a + armeabi-v7a。选 6 个分 ABI 包上传（跳过 universal 和历史残留 `app-debug.apk`，后者是 11-05 无 flavor 旧包、同 tv 包名会静默跑旧代码）。

**关键发现：yuntu 静态下载通道**。app_server 静态目录 `build/web/` **不挂在 47292 根**（`/index.html`、`/static/*` 全 404），而挂在 **47293 管理端口的 `/static/`**：
- `http://143.203.52.132:47293/static/apks/index.html` → 200
- APK → 200、`Content-Type: application/vnd.android.package-archive`、支持 Range
- 47292 只有 `/healthz` 和 `/api/*`（业务/更新下载签名接口），不提供静态直链。

**上传手法**：scp 到 `/tmp/pk-apks/` → `install -o honghao -g honghao -m 644` 落到 `build/web/apks/`（保持属主 honghao，静态文件无需 pm2 restart）。6 包 md5 本地/远端全对齐。公网下载验证 200 + Content-Length 正确。

**注意**：yuntu 磁盘只剩 1.2G（88%），以后传大包要先 `df -h`；scp 到公网约 0.6MB/s，6 包 ~590MB 耗时 13 分钟。索引页列 flavor/ABI/包名/下载按钮。

## 诊断：apps 页面 b16 vs 电视提示 17 + 电视装不了

- **b16/17 不是 bug，是 ABI 轨 build 偏移 + universal 未同步**：`db.json` 的 `latest[potatokid-screen-tv]` apk 轨：universal→build **16**（11-18 11:01）、arm64-v8a→build **2017**、armeabi-v7a→build **1017**（均 11-18 14:44 用 `--split-per-abi` 上传，`ABI_BUILD_OFFSET` = arm64 +2000 / armv7 +1000，基础 build 17）。apps 页面不带 abi 查询→显示 universal 的 b16；电视带 abi 查询→拿到 2017。
- **关键坑（易混）**：11-21 编译的带「本地代理开关」的 6 个 **debug** 包只传到 `/static/apks/` 静态目录，**未发布到应用分发 db.json**。所以 apps 页面 + 电视应用内更新拿到的**都还是 11-18 老包**，不是新包。要进分发需另跑 `upload_parent_apks.mjs`（release 包 + admin 凭据）。
- **电视应用内升级失败 = 电视限制第三方安装**：toast「无法拉起系统安装器，请检查「安装未知应用」权限」来自 `profile_page.dart:1175`（`controller.install()` 返回 false）。原生 `MainActivity.kt` 逻辑：Android 8+ 且 `!canRequestPackageInstalls()` → 跳 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 授权页 → error；部分电视无该设置页/无 ACTION_VIEW apk 安装器 → 跳转或拉起失败。用户反馈"调不出安装权限"符合电视屏蔽侧载。替代路径：U盘+电视文件管理器，或开 ADB 用 `adb install` 装 `/static/apks/` 的 arm64 包。

- **后台 apps 页 b16 徽章的出处（源码级）**：`apps.js` 列表用 `store.latestSummary()`，而 `store.js:548-566` **摘要优先取 universal 轨**（老语义）→ universal 停在 b16，所以徽章永远显示 b16，跟 arm64=2017 无关。真正的下载入口是同页 `latestTracks`（`apps.js:27-49` 按每 ABI 轨 `getLatest`），那里 arm64 是 b2017。**所以"后台徽章 b16"和"下载列/电视 17"本来就是两个不同数据源，不是数据错乱。** 另：后台 API 需 viewer/admin 会话（`/api/admin/apps` 无 cookie 返回 400001），页面能开是因 URL 带了 viewer token。
