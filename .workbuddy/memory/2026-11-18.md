### 修复：本地代理 302 鉴权跳转源无法播放 + 签名变化导致重复（2026-11-18 晚，已落地）
- 承接前两条诊断。用户日志：广东新闻源3 `gdxw.m3u8?auth=testpub` → 代理 `playlist rewritten 3片` 成功但分片全部 404 → 熔断 → 换源失败。
- 实测根因（curl）：该源 302 跳转到 `http://<不同IP>:82/live/gdxw.m3u8?jsbt=<时间戳>&jsbk=<签名>`，
  每次跳转 **IP 都不同（GSLB：38.75→69.30→107.150）+ 签名每次变**；分片是相对路径 `gdxw/segment_N.ts`。
  旧代码用配置地址（跳转前）作 base 拼分片 → 落到错误域名/无鉴权 → 404。
- 三点修复（`hls_local_proxy.dart`）：
  1. `_fetchPlaylistWithRealUri` 用 Dio `Response.realUri`（跟随 302 后地址）作 base，master 分支同样处理；
  2. `_withAuthQuery` 把 base 上的鉴权类 query（jsbt/jsbk/auth/token/t…）继承到分片 URL，分片自带同名参数不覆盖（relay 的 t/sid/f 不受污染）；
  3. **逻辑 key 与抓取 URL 分离**：分片 hash = md5(`配置地址|原始分片行`)，与重定向 IP/签名无关 → 签名刷新后本地 seg URL 不变、缓存命中；`_hashToUrl[hash]` 每次重写刷新为带当次签名的最新 URL 供实际抓取。`_getSegment(cacheKey, fetchUrl)` 签名相应改双参；`_pruneCache` 改用 `_activeHashes`。

- 关键教训：HLS 代理拼分片必须用 `realUri` 而非配置地址；缓存 key 不能用含动态签名/GSLB IP 的完整 URL，否则签名一变就缓存穿透+播放器误判新片反复重载。

## 排查：ESP32-S3 小屏「人在时亮屏后正文变空白，只剩顶栏 1/4 + IP」（已修，oled-3.3）

现象：PIR 唤醒后屏上先出现内容，随即正文（标题/主状态/副状态/按键提示）全空，只留顶栏页码+IP+WiFi 格。

### 根因（固件 bug，非服务端）
- `struct NetSnapshot` 的标量（valid/fwKnown/hasDisplay/pageCount/title…）原本**没有默认值**；`netTask` 里是局部变量 `NetSnapshot snap;`：String 成员每轮构造为空串，标量却沿用同一栈帧上一轮的残值。
- oled-3.2 新增「PIR 跳变即时心跳」路径：`if (!screenOff && (refresh || heartbeatDue)) fetch` 被跳过 → 不拉页面仍 `publishSnapshot(snap)`，发布出 **valid=true（残值）、pageCount=4（残值）、正文全空（新构造）** 的假快照。
- `applyNetSnapshot` 据此把 scrTitle/Main/Sub/Keys 刷成空、`pageCache[0]` 写成「valid 但空」，drawScreen("","","","") → 只剩 drawStatusBar。预取也因此失效（缓存被误标 valid）。
- 二级 bug：`lastHeartbeat = millis()` 在 PIR 上报分支里也执行，PIR 抖动每几秒一次 → 60 秒心跳（也是唯一定时拉页面时机）被无限顺延。

### 修复（commit add7986，本地 main，未 push）
- `NetSnapshot` 全部标量补默认值（valid/fwKnown=false，页码=1，screenOnSec=0…）。
- 只有 `heartbeatDue` 才顺延 `lastHeartbeat`；PIR 上报改走 `pirDue` 独立路径。
- README 故障表加一条；`APP_VER` → oled-3.3。
