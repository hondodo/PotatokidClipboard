## 设计：admin「智能」Tab（自动化 + 手动控制 + 人体感应实体化）

- `docs/esp-smart-tab-design.md` 实现契约（数据模型 / 接口 / 引擎 / 异常 / 分期 / 验收）

### 关键设计决策
- **人体感应拆双状态**：`presence`（瞬时电平，2 秒回落）+ `occupied`（最近 90 秒内有移动）。只做一个必错，因为 HC-SR501 只认移动。`occupied` 服务端按 `lastEnterAt` 推算，不需要改固件。
- 实体 ID 沿用 `remote.<deviceId>` 的命名习惯：`presence.<deviceId>`，这样模板变量 `{presence.state}` 能和 `{remote.xxx.channel}` 走同一套解析。
- **触发器按响应速度分组**，并把延迟写在选项上：本机事件（人体感应/小屏按键）1 秒内、定时 ±1 分钟、HA 实体状态 **15 秒级**。不假装 HA 也能秒级。
- `holdSec` 语义 = 「进入时记 pendingAt，满 N 秒仍满足才执行，中途消失就取消」，不是「延迟 N 秒」。
- 动作执行器不重写：HA 走 `callHaService`，中控/电视走 `pushRemoteCommand`，只新增「遍历 + 逐步结果 + onError」。
- 同场景串行 + 新触发直接丢弃（不排队，避免雪崩）；跨场景并行上限 5；单动作超时 10 秒。

## 「智能」Tab P1 落地（手动控制 + 自动化 + 感应虚拟实体）

用户拍板：感应只做服务内模拟实体（不注册 HA binary_sensor）、occupied 窗口 90 秒、失败即停、不改固件。

### 代码结构
- **新模块 `pscreen_server/server/scenes.js`**：场景引擎（存储 + 归一化 + 执行 + 触发 + 感应实体）。刻意独立于 4200 行的 admin.js，执行器用注入（`runAction`/`listMachines`/`labelOf`/`checkRemote`），既复用又不必把逻辑塞进大文件。
- **admin.js 挂接**：`require('./scenes')`；`sceneEngine` 创建在 overview 路由后（`scenesFile = datas/admin/scenes.json`）；8 个接口；心跳 pir 跳变 → `onPresence`（**必须在 saveMachines 之后**，引擎读盘）；`esp/press` 解析出 action 后立即 `onButton`（不依赖按键自身动作成功）；`setInterval(...,1000).unref()` 推 holdSec 计时。
- **前端 `web/admin_js/12-smart.js`** + admin.html 顶层 Tab「智能」（在 ESP 设备分类后）+ `.smart-*` 样式。
- **`12-boot.js` 改名 `99-boot.js`**：新脚本要排在 boot 之前（boot 里引用 `loadScenes`/`bindSmartOnce`），否则首次切 Tab 报未定义。部署时远端 `rm -f admin_js/12-boot.js`。

### 关键实现决策
- `holdSec` 不是「等 N 秒再执行」，而是记录 pending + 每秒 tick 到点前**再验一次状态**；中途离开就 cancelled。避免人走过走廊误触发。
- `run(id,{force})`：手动执行 force=true 跳过 enabled 与冷却，但仍防重入（`running` Set）。
- 遥控送达数 0 在场景里**算失败**（按键那里只是提示"已发送"）——自动化没人看着，发出去没人接等于没做到。
- `delay` 动作分片等待，每 500ms 检查场景是否被停用/删除，避免「关了还在跑」。
- 结果三分：`ok` / `partial`（有失败但有继续）/ `failed`；`steps` 返回逐步结果，失败才弹明细，成功只 toast。
- 软删（`deletedAt`）+ 30 天清理；`kind` 不允许改（触发器会残留）。
- `PUT /api/admin/scenes/settings` 必须注册在 `PUT /:id` **之前**，否则被当 id 吃掉。

## 智能 Tab 的实体选择改成 ESP「插入实体」同款窗口（叠加层）
- 原状：12-smart.js 用 `createEntityPicker`（输入框 + 自建下拉菜单），只列可控制实体、没有家庭/房间/设备筛选和状态值，和 ESP 页里那套差很多。
- 硬约束：`openEntityPicker` 原来写 `root.innerHTML = ...` 整体替换 `dialog-root`，而智能编辑器本身就落在 dialog-root 里 → 直接调用会把正在填的表单清掉。
- 改法（04-ha.js）：openEntityPicker 改为**追加独立层** `const layer = document.createElement('div'); layer.className='ent-pick-layer'; root.appendChild(layer)`，函数体内 `root.` 全部换 `layer.`，`close` 从 `root.innerHTML=''` 改成 `layer.remove()`。ESP 那种「dialog-root 原本为空」的调用行为不变。
- CSS：`.ent-pick-layer { position: relative; z-index: 60 }`（`.overlay` 是 50，必须更高才盖得住下层表单）。
- 12-smart.js：HA 动作行改成「`entity-picker-input` 手填 + 「选择」按钮开 openEntityPicker」，默认 `actionableOnly: true`（动作要真能执行）；选中后回填输入框，并在下方 `.entity-picker-desc` 显示「名称｜家 · 房间｜可用动作：开 / 关」，没有可用动作时提示会失败。删掉已无用的 `pickers` 数组。
- 验证：临时页 `web/__ent_pick_test.html`（桩 state/haEntities + 真 03/04/12 脚本 + `#pick`/`#close`/`#type` 三个交互分支），无头 Chrome `--dump-dom` 抓 PROBE：叠加层存在、3 行（sensor 被 actionableOnly 滤掉）、表单仍在、dialogCount=2、选中回填 `switch.kitchen_left` 且 note 文案正确、取消后 overlay 回到 1、手填生效。截图确认视觉无重叠。验证后删除临时页。

## 弹窗保存的加载态（用户反馈「以为鼠标坏了，一直点保存」）
- 根因两条，叠加才让人以为卡死：①`openDialog` 只写了 `btn.disabled = true`，而 `.btn` 全局没有 `:disabled` 样式（连 hover 高亮都保留），点了外观零变化；②`onSave` 末尾 `await loadScenes(true)` 里 `Promise.all` 每次都重拉 `/api/admin/ha/entities`（上千实体），弹窗要等它才 `close()`，空窗期好几秒。
- 改法（03-dialogs.js）：新增 `setBtnBusy(btn, text)` 通用忙态（`.is-busy` + `::before` 转圈 + 改文案 + 禁用，返回 restore）；`openDialog` 底部加 `.dialog-busy` 青色状态条（`i` 转圈 + 说明文字）。**忙态延迟 120ms 出现**（`BUSY_DELAY_MS`）避免快请求闪一下；**1800ms**（`BUSY_SLOW_MS`）升级为「网络较慢，仍在保存…」；**20s** 仍未回则 `stalled=true` 解禁关闭并提示「可点取消放弃等待」，取消/遮罩此时可关且 toast 提示去刷新确认 —— 否则「保存中锁关闭」会把弹窗彻底锁死。
- 保存中锁住取消 / × / 点遮罩（防请求已发出却关窗，用户以为没存上又建一条重复的）。
- 成功路径改为 **`close()` 不等列表刷新**：`loadOverview(false)` 不再 await。
- 改法（12-smart.js）：`loadScenes` 只在 `state.haEntities` 为空时才拉实体目录；`onSave` 末尾 `loadScenes(true)` 改 fire-and-forget，失败 toast「列表刷新失败」；名称空校验就地写 `errorEl` 再 throw；「执行」按钮接 `setBtnBusy(btn, '执行中…')`（动作可能含「等待 N 秒」）。
- CSS（admin.css）：`.btn:disabled { opacity:.45; cursor:not-allowed }` + 取消 hover 高亮、`.btn.is-busy`、`.icon-btn:disabled`、`.dialog-busy`（含 `[hidden]{display:none}` 覆盖 display:flex）、`@keyframes spin`。
- 验证：临时页 `web/_busy-test.html`（桩 state/$/esc/toast/loadOverview + 真 03-dialogs.js + 真 CSS，`?mode=slow|never`），无头 Chrome `--virtual-time-budget` 400/2000/3200/22000 截图四态：保存中 / 网络较慢 / 已保存弹窗关闭 / 20s 兜底解禁。另 `--dump-dom` 抓线上 admin.html 确认脚本无致命错误。验证后删除临时页。
