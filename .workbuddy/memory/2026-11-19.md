## 设计：admin「智能」Tab（自动化 + 手动控制 + 人体感应实体化）

### 关键设计决策
- **人体感应拆双状态**：`presence`（瞬时电平，2 秒回落）+ `occupied`（最近 90 秒内有移动）。只做一个必错，因为 HC-SR501 只认移动。`occupied` 服务端按 `lastEnterAt` 推算，不需要改固件。
- 实体 ID 沿用 `remote.<deviceId>` 的命名习惯：`presence.<deviceId>`，这样模板变量 `{presence.state}` 能和 `{remote.xxx.channel}` 走同一套解析。
- **触发器按响应速度分组**，并把延迟写在选项上：本机事件（人体感应/小屏按键）1 秒内、定时 ±1 分钟、HA 实体状态 **15 秒级**。不假装 HA 也能秒级。
- `holdSec` 语义 = 「进入时记 pendingAt，满 N 秒仍满足才执行，中途消失就取消」，不是「延迟 N 秒」。
- 动作执行器不重写：HA 走 `callHaService`，中控/电视走 `pushRemoteCommand`，只新增「遍历 + 逐步结果 + onError」。
- 同场景串行 + 新触发直接丢弃（不排队，避免雪崩）；跨场景并行上限 5；单动作超时 10 秒。

### 关键实现决策
- `holdSec` 不是「等 N 秒再执行」，而是记录 pending + 每秒 tick 到点前**再验一次状态**；中途离开就 cancelled。避免人走过走廊误触发。
- `run(id,{force})`：手动执行 force=true 跳过 enabled 与冷却，但仍防重入（`running` Set）。
- 遥控送达数 0 在场景里**算失败**（按键那里只是提示"已发送"）——自动化没人看着，发出去没人接等于没做到。
- `delay` 动作分片等待，每 500ms 检查场景是否被停用/删除，避免「关了还在跑」。
- 结果三分：`ok` / `partial`（有失败但有继续）/ `failed`；`steps` 返回逐步结果，失败才弹明细，成功只 toast。
- 软删（`deletedAt`）+ 30 天清理；`kind` 不允许改（触发器会残留）。
- `PUT /api/admin/scenes/settings` 必须注册在 `PUT /:id` **之前**，否则被当 id 吃掉。
