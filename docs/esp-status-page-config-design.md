## 零、三轮理解收敛（必读）

| 项 | v0.1（错） | v0.2（半对） | **v0.3（本稿，按用户口径）** |
|---|---|---|---|
| 承载形式 | 勾选组件 + 固定槽位 | 新建 `kind:status` 独立状态页 + 4 行专属模板 | **不新建页面**；就是现有普通页，在主状态/副状态模板里写 |
| 变量入口 | 独立组件下拉 | 状态页专属「插入变量」弹窗 | **并入现有「插入实体」弹窗**，新增「系统状态」分类 |
| 混编 | — | 状态页内可混排 | **和 HA 实体、遥控状态标签在同一模板框混编**，同一解析器 |
| 状态栏 | — | 也做成模板让用户写 | **不做模板**：勾选 显示/隐藏 + 勾选显示哪些元素；隐藏时普通页上移、按实际布局重排 |
| 页脚（按键行） | — | 可写模板 | **不可自定义**，保持现状（有按键时自动显示按键提示行） |

**一句话原则：不加新页、不加新语法。只做三件事——给「插入实体」弹窗加一个系统变量分类、给状态栏加一组勾选、给图片加黑白点解析。天气是分类里的一个带参变量，和 `{switch.xxx}` 写法一致。**

## 一、目标与范围

### 1.1 要解决什么

| 编号 | 现状 | 目标 |
|---|---|---|
| R-01 | 模板只能引用 HA 实体；想显示「联网/信号/有人/时间」得造假实体 | 「插入实体」弹窗新增「系统状态」分类，`{sys.*}` 和真实实体一样点选插入主/副状态模板 |
| R-02 | 顶部状态栏固件写死 `页码 + IP + 三格 WiFi`，不能关也不能选 | 增加勾选配置：是否显示、显示哪些元素；隐藏后内容区按实际布局重排 |
| R-03 | 天气/农历中控 App 有，ESP 拿不到；服务端直连 API 有限流 | 服务端按城市缓存下发为带参系统变量，`{sys.weather.auto}` / `{sys.weather.<id>}` 一页可多城市，失败按固定链降级 |
| R-04 | 图片无法上屏 | 新增 1-bit 黑白点解析，`{image}` 作为模板变量引用 |

### 1.2 本期包含（Must）

- **复用现有页面编辑器**：不新增页面类型、不新增独立模板输入框。用户仍在同一页的「主状态模板 `tplMain` / 副状态模板 `tplSub`」里写。
- **「插入实体」弹窗新增「系统状态」分类**（与现有「家庭/房间/设备」并列一组），列出内置变量，点击插入到光标处，插入的 token 就是 `{sys.time}` 这种。
- 内置变量可与现有 `{switch.xxx}`、`{main}/{s1}/{s2}`、`{title}`、遥控状态标签**同框混编**，走同一解析器。
- **状态栏勾选配置**（设备级）：显示/隐藏总开关；页码、时间、WiFi 图标、WiFi 强度、IP 逐项勾选。隐藏时内容区上移，按实际布局重排。
- **图片解析**：上传图片 → 转 128×64 **1-bit 黑白点**（仅阈值二值化，无灰度/抖动）→ `{image}` 变量引用 → 下发。
- 服务端天气代理（按城市 id 缓存 + 模板按需取数）+ 农历计算 + 时间下发。

### 1.3 本期不包含（Won't）

- 不新建 `status` 页面类型，不做独立状态页编辑区（v0.2 方向作废）。
- 状态栏**不做模板**（不能写 `{...}` 自由拼），只做勾选；页脚按键行**不可自定义**。
- 图片**不做灰度、不做抖动**（OLED 单色屏，灰阶无意义）；只做黑白点。
- 不重新发明模板语法：花括号、`{entity.attr}`、缺值省略、超长跑马灯，全部沿用现有规则。
- 不把 `presence.<deviceId>` 注册成 HA 实体（沿用已拍板 D-01）。
- 不做 home 端 App 顶栏（除非确认「中控」指的是它）。

## 三、详细设计

### 3.1 用户操作流程（和现在几乎一样）

```
进 ESP 设备页 → 选中任意普通页 → 编辑「主状态模板 / 副状态模板」
   → 点旁边「插入实体」→ 弹窗里多出一组「系统状态」
   → 点「时间」「有人」「天气·自动」等 → {sys.time}{sys.occupied}{sys.weather.auto} 插进模板
   → 天气要指定城市就点「天气·广州」「天气·湛江」→ {sys.weather.gz}{sys.weather.zj}，一行可并排多个
   → 想显示图片就点「图片 128×64」→ {image} 插进模板
   → 保存下发（和现在同一套流程）
```

- **主状态模板 `tplMain` / 副状态模板 `tplSub`** 就是现在的两个输入框，不改字段名、不改解析逻辑。
- 「插入实体」弹窗保持现在的叠加层交互（`openEntityPicker`），新增一组分类即可。
- 一个模板框里可以同时有 `{switch.kitchen}` + `{sys.time}` + `{image}`，顺序由用户决定。

### 3.2 「系统状态」分类里的变量清单

| 变量 | 输出示例 | 数据来源 | 刷新 |
|---|---|---|---|
| `{sys.online}` | 已联网 / 未联网 | 本机 `WiFi.status()` | 绘制时 |
| `{sys.wifi}` | `▁▃▅▇` 信号格 | 本机 `WiFi.RSSI()` | 绘制时 |
| `{sys.rssi}` | `-58dBm` | 本机 `WiFi.RSSI()` | 绘制时 |
| `{sys.present}` | 有人 / 无人 | 本机 GPIO 原始电平 | 跳变即时 |
| `{sys.occupied}` | 占用中 / 空闲 | 本机 GPIO + 90 秒窗口 | 跳变即时 |
| `{sys.time}` | `14:57` | 服务端 epoch + 时区，设备本地走秒 | 配置拉取时校准（约 60s） |
| `{sys.timeSec}` | `14:57:08` | 同上 | 同上 |
| `{sys.date}` | `11-19 周四` | 同上 | 同上 |
| `{sys.lunar}` | `十月初十` | 服务端计算（无 API） | 每日 |
| `{sys.weather.auto}` | `晴 26°` | 服务端缓存（出口 IP 反查） | TTL 30 分钟 |
| `{sys.weather.gz}` / `{sys.weather.zj}` … | `多云 29°` | 服务端缓存（按城市映射表 id） | TTL 30 分钟，一页可多城市 |
| `{sys.ip}` | `27.47.9.204` | 本机 `WiFi.localIP()` | 绘制时 |
| `{sys.page}` | `4` | 当前页 | 翻页时 |
| `{sys.total}` | `5` | 总页数 | 翻页时 |
| `{sys.pageOf}` | `4/5` | 组合 | 翻页时 |
| `{image}` | 图片（见 3.5） | 页面配置里的 1-bit 点阵 | 随配置下发 |

> 示例值均为虚构示意。`sys.` 前缀用于和 HA 实体 `domain.entity` 区分。**状态栏专用元素（页码/时间/ WiFi 图标等）也来自这张表，但状态栏是勾选显示、不是写模板**——两者数据源共用，展示方式不同。

### 3.3 解析规则（全部沿用现有，零新增语法）

- 缺失值的变量：**整段省略**，不留 `--`、不留空括号（现有约定）。
- 超长行：按现有「各行节拍跑马灯」滚动，预览只显示首屏。
- 值替换：现有 `valueMap` / `entityValueMap` 对 HA 实体照常生效；`sys.*` 已是可读文本，不走替换。
- 变量可重复写、可和文本混排：`人在 {sys.present} · {sys.time}` 合法。
- 未知变量：建议**原样保留 `{xxx}`** 方便发现拼写错误（待确认；现有实体缺失是省略，这里需特例）。

### 3.4 状态栏：勾选配置 + 按实际布局重排

配置存在设备级 `espScreen.statusBar`（新增可选字段，不改现有字段）：

```json
"espScreen": {
  "onSeconds": 60,
  "statusBar": {
    "enabled": true,
    "showPage": true,
    "showTime": true,
    "showWifiIcon": true,
    "showRssi": false,
    "showIp": true
  }
}
```

| 字段 | 含义 | 默认 |
|---|---|---|
| `enabled` | 状态栏总开关 | `true`（保持现状） |
| `showPage` | 页码 `4/5` | `true` |
| `showTime` | 时间 `14:57` | `false`（128px 塞不下全部，默认关） |
| `showWifiIcon` | WiFi 信号格图标 | `true` |
| `showRssi` | WiFi 强度数值 `-58dBm` | `false` |
| `showIp` | 设备内网 IP | `true`（保持现状） |

**排版规则（关键）：**

- 128×64 单行状态栏只有约 122px 可用，全开必然超宽——所以逐项勾选，由用户取舍。
- **状态栏显示时**：顶部 10px 画状态栏，内容区从 y=22 开始（标题/主/副/按键四行，与现状一致）。
- **状态栏隐藏时（`enabled=false`）**：内容区整体上移约 12px，标题提到 y=10，主/副/按键依次上移；**空出的顶部空间归还内容区**，超长文本滚动区域更大，不浪费顶部一条黑边。
- 超宽处理：勾选组合超出 128px 时，admin 实时预览给红色提示「状态栏元素过多会截断」，并建议关掉某几项；**不自动删用户勾选项**。
- 页脚（按键提示行）：**不可自定义**，有按键时固件自动显示在末行。

### 3.5 图片解析：1-bit 黑白点

- 上传图片 → 浏览器 canvas 裁/缩放到 128×64 → **灰度后按单一阈值二值化 → 每像素 1 bit，共 1024 字节** → base64 约 1.4KB 存进页面配置。
- **明确不做**：灰阶、抖动（dither/floyd-steinberg）、透明度。OLED 是单色屏，这些没有意义且会放大文件。
- 反色（黑底白点 ↔ 白底黑点）：作为可选转换项保留（待确认是否要），因为不同来源图片明暗不一。
- **显示图片开关（v0.6 落码口径）**：图片归「屏幕显示内容」，不再靠模板 token。上传图片后**自动勾选「显示图片」**；勾选时主/副状态模板、值替换、按实体替换四个输入框及「插入实体」按钮禁用，并显示「正在使用图片显示，上方内容编辑已锁定；取消勾选后可继续编辑（原内容会保留）」。整页只出点阵图，标题/正文/按键提示全部留空。取消勾选即解锁，已填内容原样保留。
  - **兼容**：老配置没有 `enabled` 字段时，模板只写 `{image}` 仍按纯图片页处理；`{image}` 在正文里恒为空串，绝不把 base64 塞进 `DISPLAY` 行（否则真机滚乱码）。
- 下发：图片点阵随页面配置下发独立行 `IMG|<pageId>|<base64>|<invert>`；固件解码后作为显存点位绘制。admin 预览里的点阵块即真机实际效果，不再写 `[图片]` 占位字样。
- 建议每设备最多 4 张、单图 ≤2KB（待确认）。

### 3.6 天气 / 农历 / 时间的来源与降级

#### 3.6.1 带参天气变量 + 城市映射表（v0.4 重构）

**需求来源（用户口径）**：要写成 `{sys.weather.auto}` / `{sys.weather.<城市id>}`，城市 id 从「我们的表」生成映射；一个页面里能并排 `广州 xxx｜湛江 xxx`。**明确不做手填经纬度。**

**事实基线（已核对代码，沿用不臆造）：**
- home 端共享包 `AppConfig.weatherCities` + `assets/datas/weather_cities.txt`（当前 `湛江,广州,佛山`），空串 = 自动（IP 反查）——可作为城市 id 映射的初始城市名来源。
- 天气 API 为心知 V3，`location` 支持「城市名」或 `lat:lon`；免费版城市覆盖有限，未覆盖抛 `AP010006` → 回退默认城市（湛江）。
- 服务端 `admin.js` 目前无天气代理接口，ESP 走服务端代理是**新增接口**。

**变量语法（和 `{switch.bedroom}` 同一套解析器，无新语法）**

| 写法 | 含义 | 取数 location | 输出 |
|---|---|---|---|
| `{sys.weather.auto}` | 自动 | 服务端出口公网 IP 反查 | 该地天气短文本，如 `晴 26°` |
| `{sys.weather.gz}` | 指定城市 | 按 id 查映射表 → `广州` | 广州天气短文本 |
| `{sys.weather.zj}` | 指定城市 | → `湛江` | 湛江天气短文本 |
| `{sys.weather.<未定义id>}` | 拼错 / 已删 | 无 | 整段省略（不留 `--`） |

- 变量只输出**天气短文本**（`晴 26°`），城市名由模板里的普通文本写（如 `广州 `）——与现有「标签手写、变量出值」约定一致，也避免屏幕宽度被城市名重复占用。
- 一页多城市就是把多个带参变量写进同一模板：`广州 {sys.weather.gz}｜湛江 {sys.weather.zj}`。128×64 一行放不下时按现有节拍跑马灯；也支持分别写在主状态 / 副状态两行。

**城市映射表（唯一真源，新增设备无关的全局配置）**

```json
"weatherCities": [
  { "id": "auto", "name": "自动", "location": "" },
  { "id": "gz",   "name": "广州", "location": "广州" },
  { "id": "zj",   "name": "湛江", "location": "湛江" },
  { "id": "fs",   "name": "佛山", "location": "佛山" }
]
```

- `id`：小写字母/数字，模板里跟在 `sys.weather.` 后；**一经下发不可随意改**（改了等于新变量），改名走「删旧增新 + 模板替换」。
- `name`：admin 展示名；`location`：传给心知的查询值（默认 = 城市名）。
- 初始化从 `weather_cities.txt` 生成（中文名 → 拼音缩写 id，如 `gz/zj/fs`，生成后人工校对）；admin 可增删行，`auto` 行固定不可删。
- **不开放 `lat:lon` 手填**：location 只由映射表维护，避免用户输错坐标与后续清洗成本。

**服务端代理（ESP 不直连 API，规避 key 泄露与限流）**

- 配置下发时**扫描所有页面模板**，收集实际用到的城市 id 集合（去重，含 `auto`），只对这批 id 取数——没写进模板的城市不请求。
- 逐个 id 解析：`auto` → IP 反查；指定 id → 查映射表 location → 心知 V3 `/weather/now.json` → 归一化短文本 `晴 26°`。
- 缓存 **key = id**（比按 location 更稳，映射表改名不影响缓存命中），**每个 id 独立 TTL 30 分钟、全设备共用**；IP 反查结果额外缓存 24h。N 台设备引用同一 id 只打一次心知 API，免费版限流可控。
- 下发一个天气字典：`"weather": {"auto":"晴 26°","gz":"多云 29°","zj":"晴 26°"}`；设备解析 `{sys.weather.gz}` 时查该字典。
- server 拿到的是**自己的出口公网 IP**，所以 `auto` 定位的是服务器所在地（部署机在哪按哪），与 home 端现状一致。

**降级链（逐 id 独立，屏上永不显示 `--`）**

1. 命中该 id 未过期缓存 / API 成功 → 正常输出；
2. API 失败 → 该 id 上次成功缓存（哪怕过期，标 stale）；
3. **仅 `auto`**：无缓存 / AP010006 → 回退默认城市湛江（语义仍是「本地附近」）；**指定 id 不做跨城市回退**——写的是广州就不能塞湛江的天气，否则显示错城市，宁可省略；
4. 全部失败 → 该变量输出空，整段省略。
- 每级打 admin 日志（实时/缓存/stale/回退/空 + id），排障不打扰用户。

**admin 可见状态**

- 城市映射表管理：id / 城市名 / location 的增删改（`auto` 固定），生成到「插入实体」弹窗的天气分组。
- TTL（30/60/120 分钟）、默认城市（供 `auto` 回退）。
- 状态行：`各活跃 id · 解析后城市 · 数据来源（实时/缓存/stale/回退）· 上次更新 · 下次刷新倒计时`。
- 心知 key 与默认城市从服务端配置/环境变量读，**不下发到 ESP**，避免私钥泄露。

#### 3.6.2 城市 id 生命周期管理（新增城市 / 拼音冲突 / 改名删除）

**核心原则：城市 id 是模板里的"契约"，不是普通配置项。** 一旦 `{sys.weather.zj}` 被写进某台设备的模板，它就绑定了"湛江"这个语义；任何静默的 id 漂移都会让屏幕显示错城市的天气（比显示空更糟——用户会当成真的）。因此所有 id 变更必须显式、可追溯、有引用检查。

**一、新增城市的完整链路（6 步，无需改固件）**

1. **入口**：admin「天气城市映射表」→「新增城市」，填城市名（如 `镇江`）。
2. **生成 id**：中文名转拼音首字母（`镇江` → `zj`），服务端生成，用户可改。
3. **唯一性检测**：查映射表 id 是否被占用；同时扫描所有设备模板看该 id 是否已被引用。
4. **冲突消歧**：未占用 → 用短名 `zj`；已占用 → 自动降级为全拼 `zhenjiang`，全拼再撞 → 追加序号 `zhenjiang2`（详见下文）。
5. **落库**：写入全局映射表 `{id, name, location}`；`auto` 行固定。写入即触发所有在线设备配置刷新。
6. **生效**：「插入实体」弹窗的天气城市分组动态出现新变量；用户把 `{sys.weather.zhenjiang}` 写进模板 → 服务端扫描到该 id → 按 id 取数塞进天气字典 → 下发 → 固件按通用规则解析。**固件解析逻辑不随城市增减变化，无需 OTA。**

**二、拼音缩写冲突：为什么会发生、怎么解**

真实撞车很常见（首字母缩写天然非唯一）：湛江 `zj` / 镇江 `zj`、广州 `gz` / 赣州 `gz`、中山 `zs` / 舟山 `zs`、南京 `nj` / 南宁 `nn`。所以不能只靠首字母。

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 追加序号 | `zj` / `zj2` | 短 | `zj2` 看不出是哪个城市，admin 列表和模板里都是谜 | 不推荐 |
| B. 全拼 | `zhenjiang` | 语义自解释、可手动覆盖、规则简单 | id 略长（模板里也就写一次，可接受） | **推荐** |
| C. 行政区划码 | `440800` | 国标唯一 | 屏幕/模板完全不可读，需额外对照表 | 不推荐 |

**推荐规则（B）**：首字母优先 → 被占用则降级全拼 → 仍占用（如同名异地）追加 `2/3`。全程 admin 显示「原缩写 `zj` 已被『湛江』占用，已为『镇江』生成 `zhenjiang`，可手动修改」。id 一旦落库并被模板引用即锁定。

**三、改名 / 删除：引用检查是硬闸门**

- **改名**：id 不允许直接改（改了等于新变量、旧模板静默失效）。确需改走「新增新 id → 批量替换所有设备模板里的旧 token → 确认无引用后删旧 id」。admin 提供「批量替换引用」工具，替换前显示影响设备数与页面数，需二次确认。
- **删除**：删前扫描所有模板；**有引用则禁止删除**并提示「N 台设备的 M 处模板仍在使用」，逼用户先替换；无引用才允许删。删后旧 token 在预览中标黄提示「变量已失效」，输出空。
- **city name / location 可改**：改城市显示名或心知 location 不影响 id 与缓存命中（缓存 key = id），可自由改，改后下次刷新生效。

**四、批量初始化校验**

从 `weather_cities.txt`（湛江/广州/佛山）首次生成映射表时，逐个转拼音缩写并跑同一套唯一性检测；生成结果在 admin 以草稿形式展示、人工校对确认后才落库，避免初始化就埋下冲突。

#### 3.6.3 农历与时间
- **农历**：服务端移植 `packages/pscreen_screen/lib/features/time/domain/lunar_calendar.dart` 算法，无第三方 API 消耗。
- **时间**：服务端下发 epoch + 时区偏移，设备本地按 `millis` 走秒，不新增 NTP 依赖；配置拉取时校准（约 60 秒一次）。

#### 3.6.4 城市配置入口与 home / tv 的共用边界（已核对代码）

用户问："要新增编辑城市的入口吗？它们跟 home/tv 共用吗？" —— 先给事实，再给结论。**一句话：城市数据分三层，只有"可选名单"适合同源，另外两层本来就该各管各的。**

**事实基线（逐项核对源码）**

| 层 | home / tv 现状 | 证据 |
|---|---|---|
| ① 可选城市名单 | `weather_cities.txt`（当前 `湛江,广州,佛山`）编译进共享包 `assets/datas/`，同时走 `DataFiles` 优先级链：网络 → 本地缓存 → 包内 assets → `.env` 兜底。**网络地址写死为外网 `http://ptool.w1.luyouxia.net/api/screen/`，不是本地 admin 服务**。tv 启动会 `ensureSynced()` 联网更新名单，home 只读本地/包内、不联网更新 | `packages/pscreen_screen/lib/app/config/data_files.dart:30,39-43,140-177`；`app_constants.dart:30,48`；tv `potatokid_screen/lib/main.dart:86,137`；home `pscreen_home/lib/main.dart:74` |
| ② 用户选中的城市 | `AppSettings.weatherCity`，**设备本地 SharedPreferences**（键 `app_weather_city_v1`），空串=自动 IP 定位；home 与 tv 共用这份代码定义，但**每台设备各存一份，服务端不存** | `app_settings.dart:31,75,124,184-186,268-277`；home `settings_page.dart:391-397,531-560`；tv `profile_page.dart:102-143,364-371,605-628` + `app_bloc.dart:145-147` |
| ③ 心知 key / location | 客户端**自带 key 直连心知**，用城市名当 location | `weather_api_service.dart`、`weather_repository_impl.dart:26-31` |
| admin 现状 | `weather_cities.txt` 被标为 `readonly / editable:false`；**admin 页无任何天气城市编辑入口**，服务端无城市读写专用 API（只有通用只读路由 `/api/screen/:filename`） | `server/programs.js:40,684,797-824`；`server/server.js:984-1019`；`web/admin.html:263` |

**三层共用判断**

| 层 | 共用吗 | 理由 |
|---|---|---|
| ① 可选城市名单 | **同源，各自维护**（推荐） | 语义相同（"支持哪些城市"），但 home/tv 的名单源头是外网 ptools + 编译进 APK，与本地 admin 不在同一可写域，做不到运行时实时同一份 |
| ② 用户选中的城市 | **不共用，也不该共用** | home/tv 是"这台设备显示哪个"的单值；ESP 是"这个模板这一行显示哪个"的带参变量、一页可多个，语义和粒度都不同 |
| ③ 心知 key / location | **key 不共用** | key 放 ESP 服务端（不下发、避免泄露）；home/tv 是客户端自带；两套取数链路互不干扰 |

**结论与推荐**

1. **是的，要新增编辑入口，且只加在 admin 一处**：管理 ESP 城市映射表。home / tv 的天气城市选择 UI **保持现状不动**——它们是单值选择，和 ESP 的带参模板不是一回事，强行统一交互会两边都别扭。
2. **①名单"同源"的正确做法**：ESP 映射表首次从 `weather_cities.txt` 生成城市名作为种子（id/name/location），之后 admin 独立维护；admin 提供「从 weather_cities.txt 重新导入」按钮（只补缺失城市、不覆盖已有 id），并在城市表顶部显示**同源状态行**（种子来源、与 home/tv 名单的差异城市数）。
3. **不做"一处改三端实时生效"**：home/tv 名单源头写死在外网 ptools 域名且 home 端编译进 APK，要改成从本地 admin 读，需动 `AppConstants.toolsBaseUrl`（影响 source.txt / final_channels.json 等所有数据文件），风险远大于收益，明确列为**本期不做**，如需要另立需求。
4. **name/location 变更的跨平台提示**：在 admin 改了某城市名字或 location 后，若该城市名仍在 `weather_cities.txt` 里，提示"home/tv 名单使用独立副本，此处改名不会同步过去"，避免用户误以为三端都改了。

## 七、验收口径（确认后写进 PRD）

- 现有普通页的主/副状态模板里，`{sys.*}` 与 `{entity_id}`、遥控状态标签可混排、可重复，解析结果与现状一致。
- 「插入实体」弹窗新增「系统状态」分类可用；点击插入的 token 能被解析器识别。
- 缺值变量整段省略，不出现 `--`；超长行按现有节拍滚动。
- `{image}` 只输出 1-bit 黑白点（无灰阶），整屏/行内两种写法预览与真机一致（行内为可选）。
- 状态栏逐项勾选生效；隐藏时普通页内容区上移、按实际布局重排，不浪费顶部空间；超宽给明确提示且真机不崩。
- 天气：`{sys.weather.auto}` 与各 `{sys.weather.<id>}` 解析正确，同一模板写多个城市 id 时各自输出对应城市短文本、可并排；未定义 id 整段省略；城市映射表由 `weather_cities.txt` 初始化、admin 可增删改；**只对模板实际引用的 id 取数**，TTL 内每个 id 跨设备只请求一次心知 API；断网/限流/AP010006 按四级降级（指定城市不跨城回退），屏上不出现 `--`，admin 有按 id 的来源日志。
- 城市管理：新增城市自动生成 id、撞车降级全拼、重复 id 被拦截；id 被模板引用时改名/删除有提示与二次确认；admin 首页城市表显示「种子来源 + 与 weather_cities.txt 差异数」，「重新导入种子」只补缺失不覆盖已有 id。
- 共用边界：home/tv 设置页的天气城市 UI 与选择逻辑零改动；ESP 改名 location 不影响 home/tv 客户端取数；服务端无新增对 ptools 外网域名的写操作。
- 旧固件收到新配置不崩、不白屏，只显示旧顶栏。
