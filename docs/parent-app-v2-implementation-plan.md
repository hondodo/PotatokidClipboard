## 1. 目标

在不丢失现有家长端能力的前提下，解决以下核心问题：

1. App 重装后，本地家长号凭据丢失，首页只显示“无设备”，没有明显的已有家长号登录入口。
2. 旧模型下编辑儿童档案会丢失档案 `sharedTo`；新模型必须确保编辑题库时不会丢失 `Quiz.sharedTo` 授权名单。
3. 保存后关联页面没有同步刷新，页面状态需要手动刷新才能校正。
4. 过渡期规则页没有显示当前操作的电视，也不能就地切换电视；新模型完成后，孩子规则归家庭，电视页只管理本台设置和档案分配。
5. “我的”页同时承载账号、电视、遥控、共享、解锁和更新，职责过多。
6. “今天”页表现为家庭聚合视图，但儿童档案仍来自单台隐式选中的电视，作用范围不清晰。

最终目标不是减少功能，而是做到：

- 账号恢复路径明确。
- 家庭级数据和电视级配置不混淆。
- 家庭规则、电视本台设置和档案分配的作用范围始终明确。
- 家庭主档案与题库副本明确区分；不再保留跨家庭档案引用和失效占位。
- 现有题库、解锁、遥控、分享、绑定等功能全部保留并重新归位。

## 2. 已确认的产品决策

以下决策已在本轮讨论中确认，实施时不再自行改变：

- [x] V4 延续浅色、深绿色品牌语言，并建立完整的深浅主题、组件和无障碍规范。
- [x] 完整形态的底部导航为“今天 / 孩子 / 电视”。
- [x] 账号与低频设置从右上角头像进入，不再使用内容过载的“我的”Tab。
- [x] “今天”只展示家庭聚合状态，不保存隐式的当前配置电视。
- [x] “孩子”负责家庭儿童档案、家庭规则、电视分配、题库授权和题库副本导入。
- [x] “电视”负责绑定、解绑、重命名、遥控及设备级设置。
- [x] 过渡期旧规则页必须明确显示当前配置电视并支持就地切换；家庭级模型切换后，孩子页不再设置“当前电视”。
- [x] 跨家庭只分享题库内容：授权后由对方复制副本到自己的孩子名下；不分享档案、规则、身份、时长、观看记录或头像。

**D-02 回退口径**：仅在 2.3 / 2.4 的模型契约复核失败（电视端 config 投影无法落地，或题库授权契约无法收敛）时，退回「呈现层家庭化、写入层电视化」并另立需求。**在 2.3 落地到代码前，不得按新模型删除 `sharedTo` / `shared[]` / 三态视图等现有能力。**

**D-02 升级后的形态**：家庭主档案归家长号、按 `childId` 全局唯一；「档案 → 电视」分配表归 `deviceId × childId`；服务端按 `deviceId` 投影已分配档案下发 config；`sharedTo` 挂在**题库实体**上，专用于跨家长号分享题库（复制副本，不传 `childId`）；题库与头像按家庭 `childId` 分库；观看时长按家庭 `childId` 在**同一家庭内**全局累计，跨家庭不共账。

**D-03 唯一例外建议**：「批准解锁请求」是即时命令下发（`parental_unlock`），不写 `parental` 配置，建议保留为只读代管下唯一允许动作，否则代管失去核心价值。此口径默认执行，可一句话收窄为严格只读（连批准也禁用）。

### 2.2 家庭级主档案升级：影响面与语义定稿（2026-11-13 盘点）

**前提已确认**：当前全部为测试机、仍处开发阶段。下列成本因此可以归零，不再作为反对理由：`machines.json` 的 `children[]` / `sharedTo` / `shared[]` 存量合并、题库按 `deviceId` 分库的迁移、`events.jsonl` 历史时长与 `anchorKey` 重算、电视端本地缓存清理、线上老客户端兼容与灰度窗口。测试数据可清空重建，不写迁移脚本。

**但不能「直接」升级的三件事（与是否测试机无关）**：

1. **电视端硬阻塞**：服务端 config 是原样透传 `machine.parental`（`pscreen_server/server/admin.js:920-921`、`:2285-2297`），电视端 `ParentalConfig`（`packages/pscreen_screen/lib/core/parental/parental_config.dart:193-201`）没有 `shared` 字段，`fromJson` 只解析 `children[]`，`enabled` 判定为 `mode=='on' && children.isNotEmpty`。升级后若不新增「按 deviceId 投影已分配档案」的服务端逻辑，电视端拿不到任何档案，儿童模式会直接关闭。
2. **刚上线的档案共享被题库分享替换**：`parental_share.js`（240 行，全是旧模型语义）、共享四接口、家长端三态模型（主本 / 只读引用 / 失效占位 + 四类失效原因）、以及 V2 原型画的 scope 条与三态卡片，都是「每台电视一份主本」的产物。CR-01 已采纳，共享模块收敛为「题库授权白名单 + 复制副本」；同账号跨电视引用、跨家庭档案引用与四类失效原因全部废弃，11-12 验证过的档案共享场景需按新口径重验。
3. **D-01 实现形态已变**：旧方案的 `parentalRevision` 按设备维护，升级后改为「家庭档案 / 分配 / 题库 / `DeviceLocal`」四类实体各自维护版本，冲突粒度为单档案 / 单分配 / 单题库 / 单电视本台配置。**不再按旧模型写整份版本号**，但保存状态流、冲突三选一交互、in-flight 锁与 3.7 埋点均为模型无关设计，可保留。

### 2.3 定稿模型定义与派生规则（2026-11-13，S1–S6 拍板）

**口径回显（12:17 定稿）**：S1 家庭内勾选 = 分配到电视、`sharedTo` 挂题库专用于跨家长号分享；S2 同一孩子跨电视**配额规则**唯一；S3 时长按家庭 `childId` 在同一家庭内全局累计；S4 / S5 按推荐口径；S6 原型按新模型重画；**CR-01「按分享题库改」已采纳**，Q1–Q3 按推荐同步定稿；**CR-02「解锁方式放到电视下」已采纳**，解锁方式与参数改归 `deviceId`，详见 2.5。S1–S6、CR-01、CR-02 全部定稿，**本节为模型单一事实源**。

**实体与归属矩阵**

| 实体 | 归属 | 关键字段 | 说明 |
| --- | --- | --- | --- |
| 家庭主档案 `FamilyChild` | 家长号 account | `childId`、姓名 / 年龄 / 头像、限额 / 禁看时段 / 白名单 | 全局唯一一份，**不含 `deviceId`、不含 `sharedTo`、不含解锁方式**（CR-02） |
| 分配 `Assignment` | 电视 × 档案 | `deviceId`、`childId`、`activeChildIds` | 勾选哪些档案在这台电视启用；每台电视独立 |
| 电视本台设置 `DeviceLocal` | 电视 `deviceId` | 儿童模式开关、`unlockMode` 与参数（PIN / 难度 / 答题解锁降级策略）、`activeChildIds` | **CR-02 新增**：设备侧交互配置，按台独立；同账号其它电视不共享，不写入家庭主档案 |
| 题库 `Quiz` / 头像 | 家庭 `childId` | 题目、`sharedTo[]`、`sourceAccount?`、副本标记 | 同一孩子跨电视同题；跨家庭只以**复制副本**流转，不传 `childId` |
| 当日时长账 | 家庭 `childId` | `date`、`usedMinutes` | S3 同一家庭内跨电视累加；观看事件保留 `deviceId` 作来源维度 |
| 题库授权 `QuizGrant` | 题库所属家庭 | `quizId`、`sharedTo[]` | CR-01：列出被授权的其它家长号；不产生外部档案、不做引用展开 |

**S1 定稿（含 CR-01 采纳）**：新模型下家庭本身即共享单元，同一家长号名下所有电视天然可见全部家庭主档案，**家庭内不需要 `sharedTo`**。

1. 「勾选家庭内档案分享」= **分配到电视**（电视页勾选哪些档案在本台启用，写 `Assignment`），不产生授权对象。
2. `sharedTo` 挂在**题库实体**上，专用于**跨家长号分享题库**：题库主人勾选授权给哪些家长号；对方引用时按 Q1 **复制一份副本**到自己选定孩子的题库下，不回源、不传递 `childId`；规则、时长、观看记录、头像一律不跨家庭。
3. 同账号跨电视引用、跨家庭档案引用、四类失效原因全部废弃；家长端三态简化为「本地题库 / 已导入副本（带来源家长号标签）」两态。授权在导入前被撤销或来源被删除时，该题库不再可导入；已导入的副本不受影响，也不显示失效占位。
4. 已确认**不引入**家庭成员角色表；若后续需要「家庭内按成员授权」，须另走变更评估。

**S2（CR-02 收窄措辞，结论不变）**：取消「分配级 override」。**配额与限制类规则**（限额、禁看时段、频道白名单）一律存家庭主档案，电视页只读展示，不提供按台改规则的入口。原「同一孩子在不同电视有不同限额 / 时段」能力明示下线，需在原型与帮助文案中说明。**解锁方式不属于本条所说的「规则」**：它是设备侧交互配置，按 CR-02 归 `DeviceLocal`，在电视设置里按台设置；这不构成分配级规则 override。

**S3**：时长账主键为 `(家庭 childId, date)`，在同一家庭内跨电视累加；解绑、重新绑定、换台观看均不重置当日已用时长。**S3-b 两难已消解**：跨家庭只分享题库、不共享 `childId`，B 家庭产生的时长只记在 B 自己的账上，不存在「计入主本家庭 / 按看护家庭分账」的二选一。

**Q1–Q3 定稿口径**（随 CR-01 采纳）：Q1 题库**复制副本**（一次性导入到 B 自己 `childId` 的题库，B 可自行编辑、A 后续更新不同步、无失效态）；Q2 引用时**选择挂到 B 的某个 `childId`**，不引入家庭级题库资产、不推翻 S5；Q3 本期**不做跨家庭使用统计**，仅显示「哪些家长号引用了我的题库」，后续如做也只统计答题次数 / 正确率等匿名聚合，**严禁包含观看时长、观看记录、孩子姓名**。

**S4（已确认）**：解绑不是「档案归谁」——档案属于家庭、不属于任何电视。真正要定的是这四件事：

| 子问题 | 定稿口径 |
| --- | --- |

### 2.5 CR-02：解锁方式归属回归电视本台（2026-11-13 12:17 评审反馈，已采纳）

**评审核对发现（本轮主要增量）**：这不是新增需求，而是**纠正基线内部矛盾**。第 4 节「功能不丢失对照表」自建立时就写着「解锁方式 / PIN / 答题 → 电视设置 / 明确属于哪台电视」；但 2.3 旧 S5 推荐口径把解锁方式顺手归到了家庭 `childId`，V3 / V4 原型照此实现，于是出现了「对照表说归电视、模型说归家庭、电视页显示只读」的三处不一致。更关键的是：**现状 Flutter 代码里 `unlockMode` 本就按 `deviceId` 存储**（第一轮差距分析 A6 已记录），旧 S5 等于在模型升级时无意识地删掉了「按台设置解锁方式」这一既有能力。用户这条反馈本质是防止功能丢失。

**为什么应当采纳**：解锁方式不是「给孩子的规则」，而是「这台电视上的交互通道」——远程确认依赖实时通道、PIN 依赖电视端数字输入、算术题 / 答题解锁依赖电视端渲染。把它放进家庭主档案的「适用于所有电视」规则区，会诱导用户以为改一次全家庭生效，而各台电视的设备状态（在线 / 离线、有无遥控器）并不相同。归类纠正后，S2「规则唯一」仍然成立：唯一的是**配额与限制类规则**（限额、禁看时段、白名单），解锁方式属于设备侧配置，不构成分配级 override。

## 3. 不可破坏的数据约束

这些约束优先级高于页面表现。任何实现如果违反其中一项，不得交付。

> 本节描述目标模型的交付约束。旧 `ParentalConfig.children/shared` 仅作为迁移前现状保留，不再作为新功能设计依据；切换前不得提前删除，切换时服务端、家长端和电视端契约必须同批次更新。

### 3.1 身份

- `DeviceCredentials.account()`：当前管理登录身份，可为自定义家长号。
- `DeviceCredentials.channelAccount()`：本机实时通道派生号，只读，不随家长号变化。
- 重装后本地 `claimedAccount/claimedPassword` 可能为空，但服务端的家长号、电视绑定和档案仍然存在。
- 客户端不得尝试根据设备号自动冒充或恢复旧家长号；必须由用户输入家长号和口令。

### 3.2 电视作用域

- 家庭主档案与家庭规则按 `childId` 写入，不依赖当前选中的电视。
- `Assignment` 与 `DeviceLocal` 写入必须携带明确的 `deviceId`；儿童模式、解锁方式、PIN 和本台档案分配不得串台。
- 页面切换电视时，本台设置必须清空或进入加载态，不能暂时显示在新电视名下。
- 没有选中电视时，禁止修改儿童模式、解锁方式、PIN 或电视分配；仍可查看和编辑家庭档案及家庭题库。

### 3.3 档案和共享

- `FamilyChild` 归家庭账号，按 `childId` 全局唯一；不含 `deviceId`、`sharedTo` 或解锁方式。
- `Quiz.sharedTo[]` 是题库的家长号授权名单；编辑题库内容不得丢失未修改的授权名单。
- 导入题库必须创建归目标家庭和目标 `childId` 所有的独立副本，并保留来源标签；不得共享源 `childId` 或回源同步。
- 来源删除或取消授权后，只影响尚未发生的导入；已导入副本不得被删除、置为只读或显示失效占位。
- 解绑电视只删除该电视的 `Assignment` 和 `DeviceLocal`，不得修改家庭档案、题库授权或已导入副本。
- 保存成功后必须使用服务端返回值校正对应实体，并刷新受影响的家庭档案、分配或题库视图。

### 3.4 保存反馈

统一采用以下状态流：

```text
本地编辑
  -> 提交中
  -> 服务端保存成功
  -> 使用服务端返回值校正配置
  -> 刷新受影响的档案 / 分配 / 题库视图
  -> 显示成功

任一步失败
  -> 保留或恢复可解释的页面状态
  -> 明确提示失败原因
```

不得先显示“已保存”，再依赖用户手动刷新判断是否真正生效。

### 3.5 并发写入保护（D-01，本期必做）

- 版本号由**服务端**维护，客户端不得自行生成或递增。
- 家庭档案、分配、题库和电视本台配置 `DeviceLocal` 各自通过统一的实体写入收口维护版本；写入口必须覆盖分配写、`Quiz.sharedTo` 授权写与本台解锁方式写。
- 冲突粒度为单档案 / 单分配 / 单题库 / 单电视本台配置，不再以整份 `parental` 作为目标模型的并发边界。
- 每次成功写入记录版本号、最后写入者与写入时间，供冲突提示使用。
- 客户端读取配置时同时取得版本号，提交时携带读取时的 `baseRevision`。
- 服务端发现版本不一致时**不得落盘**，返回专门的冲突响应，附带对应实体的服务端当前值与版本信息。
- 冲突不得被当成普通“保存失败”；必须给“查看差异 / 以我的版本覆盖 / 放弃本次修改”三条可解释路径，放弃后页面恢复为服务端当前值。
- 保存必须有 in-flight 锁，禁止连点产生多次整份 PUT。
- 新旧兼容：不带 `baseRevision` 的旧客户端维持现有行为；新客户端遇未返回版本号的服务端降级为现有行为并明确提示“服务端未启用并发保护”。不得因灰度期版本错配导致保存整体不可用。

### 3.6 admin 只读代管（D-03）

- 数据权限：admin 可见全部电视、全部儿童档案、观看记录、解锁请求、题库授权与已导入副本，不受 `machine.parents` 过滤。
- 功能权限：admin **禁止**保存配置、绑定 / 解绑 / 重命名、改家长号与口令、改显示名、题库与头像编辑、设 `Quiz.sharedTo`、导入或删除题库副本、**改本台解锁方式与 PIN（CR-02 后属电视 `deviceId` 写操作）**。admin 可打开「本台解锁方式」弹层查看，但保存按钮禁用且服务端拦截。
- 服务端必须对家长域写接口做角色拦截，仅 `role === 'parent'` 可写；现状 `currentParentOperator()` 同时放行 admin 与 parent，属于必须修的服务端口径。
- 管理员后台自有能力（用户管理、设备归属、家长分配等）不受本条约束，拦截范围以“家长域写接口”为界，不得误伤。
- 客户端禁止出现可点击但无响应的入口；只读态有统一“只读代管”标识。例外见 2.1 D-03。

### 3.7 最小可观测（随 D-01 一起交付）

至少记录：实体保存成功 / 失败（含 **CR-02 本台解锁方式保存**）、冲突发生与用户选择、关联视图刷新失败、账号恢复曝光 / 提交 / 成功 / 失败、题库授权与副本导入结果、答题解锁空题库降级触发次数。D-01 上线效果以“冲突拦截次数”与“保存成功率”为准，**无数据不得宣称修复生效**。

## 7. 页面状态要求

每个主要页面都必须覆盖以下状态：

| 状态 | 要求 |
| --- | --- |
| 首次加载 | 显示稳定尺寸的加载占位，不能闪现错误空态 |
| 无本地家长号 | 提供登录已有家长号和创建家长号 |
| 登录失败 | 区分凭据错误、无权限和网络失败 |
| 无电视 | 提供登录恢复和添加电视，不允许规则编辑 |
| 电视离线 | 允许查看配置；遥控明确不可用或发送失败原因 |
| 配置加载失败 | 保留电视上下文，提供重试 |
| 配置保存中 | 防止重复提交和切换电视造成串写 |
| 关联视图刷新失败 | 实体保存结果与页面刷新结果分别说明，不把已成功的保存误报为失败 |
| 题库授权不可用 | 尚未导入时说明来源已删除或取消授权；已导入副本继续可用 |

根据本机规则，本计划不新增或修改 `test/` 下文件。验证分为静态检查和人工场景验证。

### 8.1 静态检查

- 检查 `FamilyChild` 保存体不包含 `sharedTo`、解锁方式或 `deviceId`。

- 检查生成文件未被手动修改。
