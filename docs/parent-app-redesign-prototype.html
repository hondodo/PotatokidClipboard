页面地图

底部只有「今天 / 规则 / 我的」三个 Tab；第 7、8 页从「我的」进入。核心变化：家长号（跨设备身份）与本机实时通道号（设备身份）彻底分开——通道号永不改名、不禁用；档案挂在电视下，可跨电视「引用共享」、改主本同步。遥控常驻在「我的」页每台电视行，不依赖孩子档案。

这些改动里，需要服务端配合的 5 件

  1. 家长号与设备派生号解耦：撤销原「设置登录名」把派生号改名迁移 + 旧号禁用成墓碑的流程。家长号作为独立账号可跨设备登录，实时通道恒用各自的派生号，永不改名/禁用。
  2. 绑定关系驱动可见性：每台电视的 parents 数组决定"哪个家长号看哪几台"；同一家长号在多台手机登录，看到的电视与档案天然一致。
  3. 档案引用共享：目标电视存对主本档案的引用（来源电视 + 档案 id），而非复制；改主本规则/限额时所有引用方同步，引用方本地只读。
  4. 解锁请求持久化并带状态（待处理 / 已批准 / 已拒绝 / 已过期），替代依赖 60 秒短码 + WS 事件的瞬时模型；按孩子跨设备合并「今日时长 / 观看会话」。
  5. 把 normalizeParental() 的校验规则下沉为两端共用、并统一按档位名单语义，杜绝 App / 后台轮流编辑互相清空。

其余（路由门控、页面重组、向导、即时校验、术语统一、保存反馈一致）基本都是 Flutter 前端工作量；题库、头像、别名、私有别名等接口服务端已经具备。
