这些改动里，需要服务端配合的只有 4 件

  1. 解锁请求持久化并带状态（待处理 / 已批准 / 已拒绝 / 已过期），替代现在依赖 60 秒短码 + WS 事件的瞬时模型。
  2. 按孩子跨设备合并「今日时长 / 观看会话」，现在只有按设备上报的 parental_watch，前端无法可靠求和。
  3. 扫码绑定时把当前设备派生的家长账号回填并授权，避免「必须去 Web 后台改角色」这一跳板。
  4. 把 normalizeParental() 的校验规则下沉为两端共用、并统一按档位名单语义，杜绝 App / 后台轮流编辑互相清空。

其余（路由门控、页面重组、向导、即时校验、术语统一、保存反馈一致）基本都是 Flutter 前端工作量；题库、头像、别名、私有别名等接口服务端已经具备。
