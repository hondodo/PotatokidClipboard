设计原型 v0.4 · 已落码（v0.5）· 线上以 admin 页面为准 · 2026-11-19
v0.4 修正（天气模型）：天气由「全局一个城市」改为模板内联带参变量——{sys.weather.auto}（服务端出口 IP）和 {sys.weather.<城市id>}（查城市映射表），城市从映射表生成 id（如 gz/zj），一行可并排多个城市：广州 {sys.weather.gz}｜湛江 {sys.weather.zj}。不做手填经纬度；每个城市独立缓存与降级，指定城市失败不跨城回退。v0.3 结论保留：不新建页面、状态栏勾选、图片 1-bit 黑白点。真机生效需固件解析新变量，本页只做设计确认。

③ 天气城市映射表 全局配置 · 生成带参变量

天气不是全局一个城市，而是模板里的带参变量。下表每行生成一个变量：写 广州 {sys.weather.gz}，就在那一行显示广州天气。同一模板可写多个城市并排。城市名手动写在模板里，变量只输出天气短文本。
与 home/tv 的关系：种子来源 weather_cities.txt（湛江/广州/佛山）· 与 home/tv 名单差异 0 个 · 此处是独立副本，改名不会同步到 home/tv
自动生成拼音 id；撞车降级全拼；id 一经使用不可改
缓存 TTL（每城市独立）
auto 回退默认城市
实时状态：auto 实时 · gz 缓存 · zj 缓存 · 未定义的 id 整段省略
初始化从 weather_cities.txt（湛江/广州/佛山）生成 id；admin 可增删，auto 行固定。只对模板实际引用的 id 取数：没写进模板的城市不请求 API。降级逐 id 独立：auto 失败回退默认城市，指定城市失败不跨城回退（写广州就不能塞湛江天气）。心知 key 不下发 ESP。
