设计目标：把"哪台设备算空调 / 热水器 / 热水瓶"的判定，从 home 端 13 个写死的 xxx_summary.dart 后缀匹配，搬到这里由你配成 多条件组合规则（规则之间 OR、规则内条件之间 AND）。服务端算好后下发"设备 → 类型"，home 端用通用卡片按配置渲染，ESP 端保持哑巴显示四行文本。 这样改判定只动这一处、两端立刻生效。左侧可新建任意类型，字段/操作符/动作均为开放输入（下拉只推荐、不阻断），新 HA 属性直接填 attr.xxx 即可。

设备类型 —

判定规则 · —规则 OR · 条件 AND

一个类型可配多条规则，任一规则命中即判为该类型；每条规则内的条件必须全部满足。条件语义：设备下"存在某个实体"满足该条件（各条件可由不同实体满足）。字段/操作符是可输入的：填 attr.属性名 即可取任意 HA 属性，下拉只是常用推荐。
按实体 ID 前缀分类 ≠ domain：domain 是 button. / switch. 这种冒号前的域（太宽泛易串类）；像 xiaomi_cn_mitv_ 这种设备前缀应填 字段=实体 ID、操作符=开头是、值=前缀（会自动忽略 button. / switch. 域前缀）。命中测试里已内置这 3 个真实实体可直接试。
更稳的做法是按设备型号：字段填 device.model（如 xiaomi.tv.v1），来自 HA 设备注册表，比实体 ID 前缀稳定且语义清晰；实测 52 台设备有 51 台带 model。
