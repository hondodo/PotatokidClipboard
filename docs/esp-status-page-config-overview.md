# 交付概览：ESP 状态展示 / 状态栏 / 图片 设计稿 v0.6

## 本轮做了什么（天气模型重构）
- 按用户最新口径，**天气从「全局一个城市」改成「模板内联带参变量 + 城市映射表」**，这是 v0.4 唯一改动；v0.3 的三条结论（不新建页面 / 状态栏勾选 / 图片 1-bit 黑白点）全部保留。
- 天气变量新写法：
  - `{sys.weather.auto}` = 服务端出口 IP 反查；
  - `{sys.weather.gz}` / `{sys.weather.zj}` … = 按城市映射表 id 查心知 location；
  - **一行可并排多个城市**：`广州 {sys.weather.gz}｜湛江 {sys.weather.zj}`，变量只出天气短文本，城市名由用户手写。
- **城市映射表**（新增全局配置）：`id → 城市名 → location`，从 `weather_cities.txt`（湛江/广州/佛山）初始化（id 用拼音缩写 gz/zj/fs），admin 可增删改，`auto` 行固定。
- **明确不做手填经纬度**（按用户意见砍掉）；`lat:lon` 只由映射表维护。
- 服务端按「模板实际引用的 id 集合」取数，每 id 独立 TTL 30 分钟、全设备共用缓存；下发天气字典 `{auto,gz,zj}` 供设备解析。
- 降级逐 id 独立：实时 → 该 id 上次缓存 → **仅 auto 回退默认城市** → 空；**指定城市失败不跨城回退**（写广州不能塞湛江天气）。
- 设计说明 `docs/esp-status-page-config-design.md` 升 v0.4（新增 3.6.1 带参模型、变量表、映射表、风险 RK-06、拍板问题、验收口径同步）。
- 可点击原型 `docs/esp-status-page-config-prototype.html` 升 v0.4：副状态默认演示两城市并排、插入弹窗新增「天气城市」动态分组、状态栏 Tab 新增城市映射表管理（增删改/天气值实时可改）、去掉手填框。
- 自检：JS 语法检查（修掉一处 `const re,m` 未初始化错误）+ 注入 onerror 确认无运行时错误；无头浏览器截图覆盖「页面内容 / 插入实体弹窗 / 城市映射表管理 / 放大后的 128×64 屏幕」四视图，无重叠溢出。放大预览确认副状态行确实并排显示「广州 多云29°｜湛江 晴26°」。

## 与上一版的关键差异
| 项 | v0.3（作废） | v0.4（本稿） |
|---|---|---|
| 天气写法 | 全局 `weather.location` 一个城市 | `{sys.weather.auto}` / `{sys.weather.<id>}` 带参变量 |
| 一页多城市 | 不支持 | 一行可并排广州/湛江等多个 |
| 城市来源 | 复用 home 单字段 + 手填经纬度 | id→location 映射表（从 weather_cities.txt 初始化），**无手填** |
| 取数 | 全局一个 location | 只取模板实际引用的 id，每 id 独立缓存 |
| 降级 | 统一回退默认城市湛江 | 仅 auto 回退；指定城市失败宁可省略也不跨城 |

## 本轮追加：城市 id 生命周期管理（v0.4 补充，回答用户「新增城市 / 拼音重复」）
- 明确 **id 是模板契约，不是普通配置项**：id 静默漂移会让屏幕显示错城市天气（比显示空更糟）。
- **新增城市 6 步链路，无需改固件**：填城市名 → 自动生成拼音首字母 id → 全局唯一性检测 → 冲突消歧 → 落库 → 模板引用后服务端取数塞进天气字典下发。固件是通用 `{sys.weather.<id>}` 解析，城市增减不触发 OTA。
- **拼音冲突消歧（方案对比后推荐）**：首字母优先（湛江 `zj`）→ 被占用降级全拼（镇江 `zhenjiang`）→ 再撞加序号（`zhenjiang2`）；不推荐纯序号 `zj2`（看不出城市）与行政区划码（不可读）。真实撞车例：湛江/镇江、广州/赣州、中山/舟山、南京/南宁。
- **改名/删除硬闸门**：id 禁直接改（改=新变量），走「新增新 id → 批量替换模板引用 → 删旧」；删除前扫描模板，有引用禁止删；name/location 可自由改（缓存 key=id，不影响命中）。
- **批量初始化**：从 `weather_cities.txt` 生成时逐个跑唯一性检测，草稿人工校对后落库。
- 设计文档新增 3.6.2 节、风险 RK-07、拍板问题第 6 问；原型城市映射表加「输入城市名 + 新增」自动演示冲突降级、id 可编辑且改名做冲突拦截/引用提示。无头截图验证通过。

## 本轮追加：与 home/tv 的共用边界（回答用户「要新增编辑入口吗 / 跟 home-tv 共用吗」）
- 核实代码后的事实：城市数据分三层，**只有"可选名单"适合同源，另两层本就该各管各的**。
  - ① 可选名单：home/tv 来自 `weather_cities.txt`（编译进 APK + 外网 ptools 域名 `http://ptool.w1.luyouxia.net/api/screen/`，非本地 admin）；tv 联网更新、home 只读本地；admin 该文件 `readonly/editable:false`，无编辑入口。
  - ② 用户选中城市：`AppSettings.weatherCity` 设备本地 SharedPreferences（单值、空串=自动），home/tv 共用代码定义但各设备各存、服务端不存 → **与 ESP 模板带参（一页多个）语义不同，不共用**。
  - ③ 心知 key：home/tv 客户端自带直连；ESP 只在服务端不下发 → **key 不共用**。
- 推荐（已落文档 3.6.4 + RK-08 + 第 7 问）：**编辑入口只加 admin 一处**，home/tv UI 零改动；ESP 名单从 `weather_cities.txt` 取种子后独立维护，admin 显示「种子来源 + 与 home/tv 差异数」并提供「重新导入种子」（只补缺失不覆盖）；**明确不做"一处改三端实时生效"**——需改客户端写死的外网地址、影响 source.txt 等所有数据文件，风险大，另立需求。
- 原型城市表加「与 home/tv 的关系」状态行 + 「↻ 重新导入种子」按钮；无头验证差异计数正确（加镇江→差异 1 个多出镇江）、无运行时错误与溢出。

## 拍板结论（v0.5，已按用户回复落码）
- 第 1/2/4/6/7 项按建议值：`{sys.xxx}` 前缀、未知变量省略、天气带参 + 城市表（TTL 30 分钟、不跨城回退）、首字母→全拼→序号消歧、编辑入口只在 admin。
- 第 3 项用户覆盖：状态栏默认 **页码 + 时间 + WiFi 图标**（非原稿 IP）；**状态栏每页独立**。
- 第 5 项用户明确：图片**服务端下发，不烧固件**；浏览器本地转 128×64 1-bit。v0.6 追加：图片移到「屏幕显示内容」，上传后自动勾选「显示图片」，勾选时四个内容框与插入实体按钮禁用并提示「正在使用图片显示」，取消勾选即解锁且原内容保留；不再需要写 `{image}`（旧模板仍兼容）。
- 城市 id 一经下发不可改；删城市前检查模板引用，避免变量失效。
