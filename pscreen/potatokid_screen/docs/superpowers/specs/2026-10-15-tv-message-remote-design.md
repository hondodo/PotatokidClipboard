# 电视消息遥控（phone ↔ TV 文本/命令/上报）设计

- 日期：2026-10-15
- 状态：已评审通过（含双向上报增补）
- 关联：`2026-10-13-remote-nim-login-design.md`（TV 端云信登录，本功能的前置能力）

## 1. 背景与目标

TV 端（`pscreen/potatokid_screen`）已实现云信（NIM）账号登录。本功能建立双向消息链路：

- **下行**：家人/管理员在手机 App（`pscreen_control`）向电视发消息——文本弹浮层，命令后台执行
- **上行**：TV 登录后向系统管理员账号 `1000001` 发送登录/收看/切台上报（纯文本）
- 管理员通过云信后台**线下**预分配发送端账号（不写代码做账号管理）

账号角色：

| 账号 | 角色 | pscreen_control 可见界面 |
|---|---|---|
| `1000001` | 系统管理员 | 「群发」页 + 「会话」列表/聊天页 |
| 其他预分配账号 | 家人 | 单页「发指令」（单台目标：手动输入或扫码） |

## 2. 总体架构

```
pscreen_control (新 Flutter 项目)
  家人账号 ──文本/命令──▶ 云信 ◀──上报(仅发1000001)── TV 端 (potatokid_screen)
  1000001   ──文本/命令──▶ 云信 ◀──┘   已登录固定账号，下行处理 + 上行上报
```

- 1 对 1 与 1 对多：管理员群发页多选目标逐台发出；家人单台发送
- TV 不回消息给发送者（除上报给 `1000001` 外，无已读/回复）

## 3. 消息协议

### 3.1 下行（→ TV）：NIM 文本消息体即信封

| 形态 | 判别 | 处理 |
|---|---|---|
| 普通文本 | `trim` 后不以 `{` 开头 | 浮层显示 |
| 显式文本信封 | `{"t":"txt","content":"..."}` | 浮层显示（等价普通文本） |
| 命令信封 | `{"t":"cmd","name":"...","args":{...}}` | 后台执行 |
| 坏 JSON | 以 `{` 开头但解析失败或无 `t` 字段 | 按普通文本显示（不静默丢弃） |

命令集（首批）：

| name | args | 行为 |
|---|---|---|
| `volume_up` | — | 音量+ |
| `volume_down` | — | 音量− |
| `mute` | — | 静音切换 |
| `channel` | `name`（如 `"CCTV-5"`）或 `index` | 切台 |
| `text` | `content` | 浮层显示 |

- 未知命令名：忽略并记日志，不向用户报错
- 扩展命令只改 TV 端分发 switch，协议判别逻辑不变
- TV **不区分发送者**：管理员与家人的消息走同一处理链路
- **安全边界**：能发消息的仅限预分配账号（可信家人）；协议不携带密钥，无额外鉴权
- 非文本消息类型（图片、自定义等）：TV 端忽略

### 3.2 上行（TV → `1000001`）：纯文本通知

TV 上报服务只发给系统管理员 `1000001`，内容为人类可读纯文本（非信封）：

| 时机 | 内容 |
|---|---|
| 登录成功 | ① `{云信账号}于{yyyy-MM-dd HH:mm}使用{设备型号}登录成功。` ② `正在收看{频道名或页面名}`（在频道报频道名；不在频道报当前页面，如 `正在收看主页`/`设置`/`屏保`/`时间页`） |
| 频道切换确认后 | `切换频道：{频道名}` |
| 每 5 分钟心跳 | `已收看{N}分钟，当前频道是{频道名或页面名}`（N=登录起累计分钟） |

- **切台防抖**：长按连切/快速切台场景，切台稳定 **1 秒**后才发，只发最终一条
- 心跳：登录起每 5 分钟一次；登出停止，重新登录清零重新计时
- 设备型号：读系统机型（如 `MiBOX 4`），读不到回落 `Android TV`
- 发送失败：记日志不重试；断线期间错过的心跳不补发，靠下一次事件/心跳自然续上
- 家人账号收不到上行消息（目标固定 `1000001`）

## 4. 发送端设计（pscreen_control，`E:\Code\potatokid_clipboard\pscreen_control\`）

### 4.1 技术栈与结构

- Flutter；bloc + get_it + easy_localization（沿用 TV 端组合，不引入 GetX）
- NIM 集成照搬 TV 端已验证方式（`nim_core_v2`，`// ignore: depend_on_referenced_packages` + hide Log 的 import 约定）
- 会话/消息列表使用 NIM SDK 本地能力（`conversation_service` 会话列表/未读/置顶、`message_service` 消息流与本地消息库），不自建存储
- 平台：Android 优先

### 4.2 按账号分叉的界面

**设置页**（首次进入强制）：自己的云信账号 + token（默认 `12345678`）→ 登录；成功后持久化，下次启动自动登录（同账号已在线则跳过）。登录后按账号角色分叉：

**管理员（`1000001`）——两个入口：**

1. **群发页**（原发送页）：
   - 目标：预设列表多选（`assets/tvs.json`）+ 手动输入 + 扫码
   - `tvs.json` 格式：`[{"name":"客厅电视","account":"TV_001"}, ...]`
   - 文本模式 / 命令模式（快捷面板：音量±、静音、频道下拉）
   - 逐台发送结果反馈（「已发 2/3 台」，失败标红可重试单台）
2. **会话**：
   - 会话列表：NIM 本地会话驱动（未读数、新消息自动置顶）；标题 = `tvs.json` 对应设备名，查不到显示账号
   - 聊天页：消息流（NIM 本地消息库）+ 底部输入（文本框 + 命令快捷面板）；发送协议与群发页相同（文本 / 信封）
   - TV 上报消息（§3.2）天然出现在对应电视的会话里，可回看

**家人（其他账号）——单页「发指令」：**

- 目标**仅**手动输入或扫码（单台）；**不支持群发、不显示预设列表**
- 文本框 + 命令快捷面板，能力与协议同上（文本 → 浮层，命令 → 执行）

### 4.3 持久化与错误处理

- 持久化：登录账号；管理员另存最近勾选的 TV 目标
- 未登录时发送禁用；群发逐台 await，单台失败不影响其余
- 断线监听并提示重连

## 5. TV 端设计（potatokid_screen）

### 5.1 接收链路（下行）

1. `NimManager` 增加新消息透传流（模式同 `onLoginStatus`/`onDataSync`），仅文本消息
2. 信封解析（§3.1）分流：文本 → 浮层服务；命令 → 后台 switch
3. 未登录时收到（理论不应发生）：静默丢弃并记日志

### 5.2 浮层交互（TV 遥控器规范）

- 展示：**从上向下滑入**的浮窗卡片（顶部通知式），仅显示截断预览
- **焦点**：浮窗可见时抢占焦点；关闭后恢复抢占前的焦点位置
- 按键：全局拦截（main_app 层，模式同 `editingRemote` 拦截）——
  - **返回**：一级关闭浮窗
  - **OK**：打开详情窗（全文，D-pad 上下滚动）；详情内**返回**回到浮窗，浮窗再按返回关闭（两级返回）
- 自动关闭：浮窗可见期间**任意按键重置**计时；无操作 **1 分钟**自动关闭
- 详情窗期间暂停计时；关闭详情后重开 1 分钟
- **新消息到达**：直接替换浮窗内容（不关闭重弹），自动关闭计时重置；详情窗打开时同样替换内容
- 多条排队：显示期间的新消息按替换处理，不排队积压旧消息
- **屏保互斥**：屏保运行时收到消息缓存，退出屏保后弹出

### 5.3 二维码展示（供发送端扫码填入目标账号）

- 入口：打开「远程」行编辑浮层（按 OK 进入）时，浮层内**常驻二维码区**（已登录才显示，内容为当前账号明文）——零新手势、不新增行、不改焦点链；输入账号与展示二维码并存
- 未登录时浮层只有输入区，无二维码

### 5.4 命令执行（下行）

- `switch` 分发到现有能力：音量控制、切台、浮层（`text`）
- 后台静默执行，无 UI 反馈

### 5.5 上报服务（上行，§3.2）

1. 触发点：
   - 登录成功事件（`RemoteLoginState` → 已登录）→ 发登录两条通知 + 启动心跳定时器 + 记录登录时刻
   - 频道实际切换确认事件（所有切台路径汇合处）→ 防抖 1 秒 → 发「切换频道」
   - 登出/登录失败 → 停止定时器、清零计时
2. 发送走 NIM 发送接口（`MessageCreator.createTextMessage` + `sendMessage`，目标 `1000001`）
3. 与接收共用同一 NIM 连接；发送失败记日志不重试
4. 当前停留页面/频道名：从现有频道/页面状态读取（与浮层、命令执行同一状态源）

## 6. 测试策略

- 信封解析器：纯文本 / 合法 txt / 合法 cmd / `{` 开头坏 JSON / 未知 `t` / 未知命令名
- 接收分流：收到 → 浮层队列替换逻辑、命令 → 对应调用（Manual Fake）
- 上报服务：登录两条通知内容与目标账号、切台防抖（连发只出最终一条）、心跳 5 分钟节奏与登出停止、重登清零
- 发送端：登录角色分叉（1000001 两入口 vs 家人单页）、家人目标仅手动/扫码、管理员多选组装与逐台结果、聊天页发送与消息流刷新
- 浮层交互：焦点抢占/归还、两级返回、计时重置、新消息替换（widget 测试按需）

## 7. 不做的事（YAGNI）

- 已读回执、在线状态、离线补收、撤回
- TV 端回消息给非管理员
- 命令/协议加密、额外鉴权、在线建号
- 家人预设列表、家人群发
- 图片/文件消息、群聊（team）

## 8. 已知限制

- 协议明文走云信通道，仅依赖账号体系隔离；token 固定值与 TV 端登录功能同一约定（用户明确要求）
- 群发预设列表打包在发送端资产内，更新需发版（管理员手动输入可临时绕过）
- 断线期间错过的上报心跳不补发
- 上报目标写死 `1000001`（常量，如需多管理员后续再议）
- pscreen_control 聊天页仅显示实时消息流（历史消息本地拉取待后续）；自己发送的消息不出现在聊天流（isOutgoing 恒 false）
- pscreen_control 断线仅提示，自动重连依赖 SDK 默认行为，无手动重试按钮
- 会话列表/聊天过滤基于 localConversationService；conversationId→对方账号用 SDK conversationTargetId + 解析回退，真机需验证消息上报会话可见性
