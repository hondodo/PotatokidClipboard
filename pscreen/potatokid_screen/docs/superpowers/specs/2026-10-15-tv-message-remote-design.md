# 电视消息遥控（phone → TV 文本/命令）设计

- 日期：2026-10-15
- 状态：已评审通过
- 关联：`2026-10-13-remote-nim-login-design.md`（TV 端云信登录，本功能的前置能力）

## 1. 背景与目标

TV 端（`pscreen/potatokid_screen`）已实现云信（NIM）账号登录。本功能在此之上建立**单向消息链路**：

- 家人/管理员在手机上用新 App（`pscreen_control`）向电视发消息
- 电视收到后：普通文本弹浮层展示；命令在后台静默执行（切台、音量等）
- TV 不回消息（无已读/回复）

管理员通过云信后台**线下**预分配发送端账号（不写代码做账号管理）。

## 2. 总体架构

```
发送端 App (pscreen_control，新 Flutter 项目)
  登录预分配账号 ──P2P 文本消息──▶ 云信服务器
                                        │
TV 端 (potatokid_screen) ◀──────────────┘
  已登录固定账号，收消息 → 判类型 → 浮层 / 命令执行
```

- 两端均为 NIM 客户端；TV 端登录能力来自 remote-nim-login 功能
- 发送端 token 与 TV 端同一约定：默认 `12345678`，可编辑
- 1 对 1 与 1 对多：发送端多选目标，同一消息逐台发出

## 3. 消息协议

NIM **文本消息**，消息体即协议信封：

| 形态 | 判别 | 处理 |
|---|---|---|
| 普通文本 | `trim` 后不以 `{` 开头 | 浮层显示 |
| 显式文本信封 | `{"t":"txt","content":"..."}` | 浮层显示（等价普通文本） |
| 命令信封 | `{"t":"cmd","name":"...","args":{...}}` | 后台执行 |
| 坏 JSON | 以 `{` 开头但解析失败或无 `t` 字段 | 按普通文本显示（不静默丢弃） |

命令集（首批）：

| name | args | 行为 |
|---|---|---|
| `volume_up` | — | 音量+ |
| `volume_down` | — | 音量− |
| `mute` | — | 静音切换 |
| `channel` | `name`（如 `"CCTV-5"`）或 `index` | 切台 |
| `text` | `content` | 浮层显示 |

- 未知命令名：忽略并记日志，不向用户报错
- 扩展命令只改 TV 端分发 switch，协议判别逻辑不变
- **安全边界**：能发消息的仅限管理员预分配账号（可信家人）；协议不携带密钥，无额外鉴权
- 非文本消息类型（图片、自定义等）：TV 端忽略

## 4. 发送端设计（pscreen_control）

### 4.1 技术栈与结构

- Flutter；bloc + get_it + easy_localization（沿用 TV 端组合，不引入 GetX）
- NIM 集成照搬 TV 端已验证方式（`nim_core_v2`，`// ignore: depend_on_referenced_packages` + hide Log 的 import 约定）
- 平台：Android 优先

### 4.2 页面

**设置页**（首次进入强制）：自己的云信账号 + token（默认 `12345678`）→ 登录；成功后持久化，下次启动自动登录（语义同 TV 端：同账号已在线则跳过）。

**发送页**：

- 顶部目标选择：预设列表多选（`assets/tvs.json`）+ 手动输入账号 + 扫码（扫 TV 端二维码自动填入手动输入）
- `tvs.json` 格式：`[{"name":"客厅电视","account":"TV_001"}, ...]`
- 中部：消息输入框 + 模式切换
  - 文本模式：原文发出
  - 命令模式：快捷面板（音量±、静音、频道下拉），选完组装信封 JSON 发出
- 底部：连接状态（未登录/登录中/已登录/异常）+ 本机账号
- 发送结果逐台反馈（「已发 2/3 台」，失败标红，可单台重试）

### 4.3 持久化与错误处理

- 持久化：登录账号、最近勾选的 TV 目标
- 未登录时发送禁用；逐台 await 发送，单台失败不影响其余
- 断线监听并提示重连

## 5. TV 端设计（potatokid_screen）

### 5.1 接收链路

1. `NimManager` 增加新消息透传流（模式同 `onLoginStatus`/`onDataSync`），仅文本消息
2. 信封解析（§3 规则）分流：文本 → 浮层服务；命令 → 后台 switch
3. 未登录时收到（理论不应发生）：静默丢弃并记日志

### 5.2 浮层交互（TV 遥控器规范）

- 展示：**从上向下滑入**的浮窗卡片（顶部通知式），仅显示截断预览
- **焦点**：浮窗可见时抢占焦点；关闭后恢复抢占前的焦点位置
- 按键：全局拦截（main_app 层，模式同 `editingRemote` 拦截）——
  - **返回**：一级关闭浮窗
  - **OK**：打开详情窗（全文，D-pad 上下滚动）；详情内**返回**回到浮窗，浮窗再按返回关闭（两级返回）
- 自动关闭：浮窗可见期间**任意按键重置**计时；无操作 **1 分钟**自动关闭
- 详情窗期间暂停计时；关闭详情后重开 1 分钟
- **新消息到达**：直接替换浮窗内容（不关闭重弹），自动关闭计时重置；详情窗打开时同样替换内容
- 多条排队：显示期间的新消息按替换处理，不排队积压旧消息
- **屏保互斥**：屏保运行时收到消息缓存，退出屏保后弹出

### 5.3 二维码展示（供发送端扫码填入目标账号）

- 「我的 → 远程」行在**已登录**状态下可打开二维码浮层（OK 之外的入口，如行内「二维码」子按钮或命令面板入口，实现时定其一）
- 二维码内容：当前 NIM 账号明文（无协议前缀）；发送端扫描原文即得账号
- 未登录时不提供入口

### 5.4 命令执行

- `switch` 分发到现有能力：音量控制、切台、浮层（`text`）
- 后台静默执行，无 UI 反馈（发送端逐台发送结果即反馈）

## 6. 测试策略

- 信封解析器：纯文本 / 合法 txt / 合法 cmd / `{` 开头坏 JSON / 未知 `t` / 未知命令名
- 接收分流：收到 → 浮层队列替换逻辑、命令 → 对应调用（Manual Fake）
- 发送端：登录流程、多选目标组装、逐台结果统计、单台失败重试
- 浮层交互：焦点抢占/归还、两级返回、计时重置、新消息替换（widget 测试按需）

## 7. 不做的事（YAGNI）

- 消息历史、已读回执、离线补收
- TV 端回消息
- 命令/协议加密、额外鉴权
- 管理端在线建号（线下预分配）
- 图片/文件消息

## 8. 已知限制

- 协议明文走云信通道，仅依赖账号体系隔离；token 固定值与 TV 端登录功能同一约定（用户明确要求）
- 预设列表打包在发送端资产内，更新列表需发版（手动输入可临时绕过）
- 发送端断线期间的消息不补发（发送失败由用户重试）
